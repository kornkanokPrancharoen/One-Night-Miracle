1. IP Address & Subnetting Guide

🌐

IPv4 Classes & Range

Class 1st Octet Default Mask Purpose
A 1 - 126 255.0.0.0 (/8) องค์กรยักษ์ใหญ่ (16.7M hosts)
B 128 - 191 255.255.0.0 (/16) องค์กรขนาดกลาง (65,534 hosts)
C 192 - 223 255.255.255.0 (/24) องค์กรขนาดเล็ก (254 hosts)
D 224 - 239 - Multicast (ไม่มี Subnet Mask)
E 240 - 255 - Experimental / Research

⚠️ หมายเหตุ: 127.0.0.0/8 สำรองไว้สำหรับ Loopback (127.0.0.1 = localhost)

🔐 Private IP Address (RFC 1918) ห้าม Routing บน Internet:
  • • Class A: 10.0.0.0 - 10.255.255.255 (10.0.0.0/8)
  • • Class B: 172.16.0.0 - 172.31.255.255 (172.16.0.0/12)
  • • Class C: 192.168.0.0 - 192.168.255.255 (192.168.0.0/16)
  • • APIPA (DHCP Fail): 169.254.0.0/16 (Link-Local)
📐 สูตรคำนวณ Subnet
จำนวน Subnet = 2^s (s = บิตที่ยืม)
Usable Hosts = 2^h - 2 (h = บิตโฮสต์)
*หัก 2 คือ Network ID (ตัวแรก) และ Broadcast ID (ตัวท้ายสุด)
📐 เทคนิคการหา Magic Number (Block Size)

Magic Number = 256 - Mask Octet

ตัวอย่าง: /26 = 255.255.255.192
256 - 192 = 64
Subnets จะกระโดดทีละ 64 (0, 64, 128, 192)

NAT (Network Address Translation): Static NAT (1-to-1), Dynamic NAT (Pool to Pool), และ PAT / NAT Overload (ใช้ Public IP ตัวเดียว + แยก Session ด้วย Port Number)

2. Internet Architecture & Web Technology

🌍

TCP/IP 4-5 Layer vs OSI 7-Layer

OSI 7 Layers
  1. Physical (Bit)
  2. Data Link (Frame)
  3. Network (Packet - IP)
  4. Transport (Segment - TCP/UDP)
  5. Session
  6. Presentation (SSL/TLS, JPEG)
  7. Application (HTTP, DNS)
TCP/IP Model
  • • Application: รวมชั้น 5, 6, 7 เข้าด้วยกัน
  • • Transport: TCP (Reliable 3-way handshake) vs UDP (Fast, Connectionless)
  • • Internet: IP, ICMP, ARP
  • • Network Access: Ethernet, Wi-Fi

4. IoT Architecture & Protocols

📡

4 Layers of IoT Architecture

1. Perception Sensors, Actuators, RFID, กล้อง, GPS
2. Network Wi-Fi, 5G, BLE, ZigBee, LoRaWAN
3. Middleware Cloud Data Storage, Big Data, ML Engine

📊 การเปรียบเทียบคุณสมบัติ: MQTT vs CoAP
MQTT TCP based

• รูปแบบ: Publish / Subscribe ผ่าน Central Broker

• ทำงานบน: TCP พอร์ต 1883 (8883 บน TLS)

• Header เล็กมาก (2 bytes), มี QoS 0, 1, 2

• เหมาะกับ: สตรีมข้อมูลต่อเนื่อง ส่งข้อความหาหลายจุดพร้อมกัน

CoAP UDP based

• รูปแบบ: Request / Response (RESTful)

• ทำงานบน: UDP พอร์ต 5683 (DTLS ปลอดภัย)

• ออกแบบมาแปลงเข้า HTTP (GET/POST/PUT/DELETE) ได้ง่าย

• เหมาะกับ: อุปกรณ์หลับ (Sleeping nodes) ทรัพยากรจำกัดสุดขีด

📶 LPWAN (Low Power Wide Area Network): ระยะส่งไกลนับกิโลเมตร แบตเตอรี่อยู่ได้นานนับปี แต่ Bandwidth ต่ำ เช่น LoRaWAN (ใช้คลื่น Unlicensed sub-GHz ทำเกตเวย์เองได้) และ NB-IoT (วิ่งบนเสาโทรศัพท์ 4G/5G ของโอเปอเรเตอร์ มีค่าบริการซิม)

5. Cloud Computing Fundamentals

☁️

NIST 5 Essential Characteristics

1. On-demand Self-service: เปิดเครื่อง/จัดสรรทรัพยากรเองได้อัตโนมัติไม่ต้องโทรหาคน
2. Broad Network Access: เข้าถึงได้ผ่านเน็ตจากทุกที่และทุกอุปกรณ์ (Web/Mobile)
3. Resource Pooling: รวมทรัพยากรไว้แชร์ผู้ใช้หลายคน (Multi-tenant model)
4. Rapid Elasticity: สเกลขยาย-ลดขนาดได้ทันทีตามทราฟฟิก (Auto-scaling)
5. Measured Service: คิดเงินตามการใช้งานจริงแบบ Pay-as-you-go พร้อมมิเตอร์วัด

Service Models & ความรับผิดชอบ (Shared Responsibility)

IaaS:

Infrastructure as a Service (เช่าฮาร์ดแวร์/VM)

ผู้ให้บริการดู: Data Center, Power, Storage, Network | เราดู: OS, Runtime, DB, App, Data (เช่น AWS EC2, GCP Compute Engine, Azure VM)

PaaS:

Platform as a Service (เช่าสภาพแวดล้อมรันโค้ด)

ผู้ให้บริการดู: ฮาร์ดแวร์ + OS + Runtime + Patch | เราดู: เฉพาะ Application โค้ดและ Data (เช่น Heroku, Firebase, App Engine)

SaaS:

Software as a Service (ซอฟต์แวร์สำเร็จรูปพร้อมใช้)

ผู้ให้บริการดูแลทั้งหมด 100% | เราเป็น: ผู้ใช้ปลายทาง End User (เช่น Google Workspace, Microsoft 365, Canva)

Public Cloud: ให้บริการสาธารณะทั่วไป · Private Cloud: รันเฉพาะองค์กรตนเองเพื่อความปลอดภัย · Hybrid Cloud: ผสม On-premise + Public Cloud

6. Information & Network Security

🛡️

CIA Triad (เสาหลักความมั่นคงปลอดภัย)

C - Confidentiality ความลับ ข้อมูลไม่รั่วไหล (แก้ด้วย Encryption, ACL)
I - Integrity ความถูกต้อง ไม่ถูกแอบดัดแปลง (แก้ด้วย Hashing, Sign)
A - Availability ความพร้อมใช้งาน ระบบไม่ล่ม (แก้ด้วย Redundancy, HA)

Malware & Threat Classification

Virus vs Worm: Virus ต้องอาศัยไฟล์ Host ในการแพร่พันธุ์ ส่วน Worm สามารถแพร่กระจายข้ามเครือข่ายได้เองโดยอัตโนมัติ
Trojan Horse & Ransomware: Trojan แฝงตัวมากับโปรแกรมที่ดูปลอดภัย ส่วน Ransomware เข้ารหัสไฟล์เรียกค่าไถ่
Phishing & Social Eng: หลอกลวงเหยื่อด้วยอีเมล/เว็บปลอมเพื่อให้กรอกรหัสผ่านหรือข้อมูลบัตรเครดิต
DDoS & MITM: DDoS ยิงทราฟฟิกมหาศาลให้เซิร์ฟเวอร์ล่ม ส่วน MITM (Man-in-the-Middle) ดักฟังหรือแทรกกลางการส่งข้อมูล
🔥 อุปกรณ์ป้องกันเครือข่าย:

• Firewall: ตรวจสอบ IP/Port/State กรองอนุญาตหรือปฏิเสธแพ็กเก็ต (Allow/Deny rule)

• IDS (Intrusion Detection System): ตรวจจับและ แจ้งเตือน (Alert) อย่างเดียว ไม่ขวางทางส่งข้อมูล (Passive / Out-of-band)

• IPS (Intrusion Prevention System): ติดตั้งแบบ In-line ตรวจจับและ บล็อกทิ้งทันที (Drop packet) แบบเรียลไทม์

1. SDLC Models: Waterfall vs Agile / Scrum

🔄

ตารางเปรียบเทียบ Waterfall vs Agile

มิติการเปรียบเทียบ Waterfall (เชิงเส้น/ดั้งเดิม) Agile / Scrum (วนซ้ำ/ยืดหยุ่น)
กระบวนการ เรียงลำดับขั้นตอน (Sequential) ทำทีละเฟส ย้อนกลับยาก ทำซ้ำแบบวนรอบ (Iterative & Incremental) สปรินต์ 1-4 สัปดาห์
Requirements ต้องชัดเจน 100% ตั้งแต่แรก ห้ามเปลี่ยนกลางคัน ปรับเปลี่ยนได้ตลอดเวลา ยินดีรับ Feedback
ผลงานซอฟต์แวร์ เห็นตอนจบโครงการทีเดียว (Late risk discovery) ส่งมอบ Working Software ชิ้นเล็กๆ ทุกจบ Sprint
เหมาะกับงานแบบไหน ระบบความปลอดภัยสูง สเปกนิ่ง เช่น ระบบการแพทย์, ดาวเทียม สตาร์ทอัพ, เว็บ/แอป, ตลาดแข่งขันสูงที่ความต้องการผันผวน
🏉 องค์ประกอบสำคัญของ Scrum Framework:
3 บทบาท (Roles):
  • • Product Owner: จัดการ Backlog ลำดับความสำคัญ
  • • Scrum Master: ขจัดอุปสรรค ดูแลกระบวนการ
  • • Developers: สร้างชิ้นงานส่งมอบ
4 พิธีกรรม (Events):
  • • Sprint Planning: วางแผนงาน
  • • Daily Standup: คุยสั้น 15 นาที
  • • Sprint Review: เดโมงานให้ลูกค้า
  • • Retrospective: ทบทวนปรับปรุงทีม
3 ชิ้นงาน (Artifacts):
  • • Product Backlog: งานรวมทั้งหมด
  • • Sprint Backlog: งานในรอบสปรินต์นี้
  • • Increment (DoD): ซอฟต์แวร์พร้อมใช้งาน

2. Database Normalization (1NF, 2NF, 3NF)

🗄️

เป้าหมายของการ Normalize: ลดความซ้ำซ้อนของข้อมูล (Data Redundancy) และแก้ปัญหาความผิดปกติเมื่อเพิ่ม (Insertion), แก้ไข (Update), หรือลบ (Deletion) ข้อมูล

🥇 1NF (First Normal Form): Atomicity Atomic Values

เงื่อนไข: แต่ละคอลัมน์ต้องเก็บค่าเดี่ยว (Atomic value) เท่านั้น ห้ามมี Repeating groups หรือค่าที่คั่นด้วยจุลภาค (เช่น "Java, Python, C++" ในช่องเดียวต้องแยกออก) และต้องมี Primary Key

🥈 2NF (Second Normal Form): No Partial Dependency Full Dependency

เงื่อนไข: ต้องเป็น 1NF และ ไม่มี Partial Functional Dependency (ทุกคอลัมน์ที่ไม่ใช่คีย์ ต้องขึ้นตรงกับ Composite Primary Key "ทุกตัวแบบเต็มตัว" ไม่ใช่ขึ้นแค่บางส่วน)

💡 วิธีแก้: หากตารางมี Composite PK เช่น (StudentID, CourseID) แล้วมีคอลัมน์ CourseName ที่ขึ้นตรงกับแค่ CourseID ตัวเดียว ➜ ให้ตัด CourseName ออกไปสร้างตาราง Course ใหม่

🥉 3NF (Third Normal Form): No Transitive Dependency No Transit

เงื่อนไข: ต้องเป็น 2NF และ ไม่มี Transitive Dependency (คอลัมน์ที่ไม่ใช่คีย์ ห้ามไปขึ้นต่อกับคอลัมน์อื่นที่ไม่ใช่คีย์ด้วยกัน เช่น A ➜ B และ B ➜ C)

💡 วิธีแก้: ตารางพนักงานมี (EmpID, DeptID, DeptName) โดย DeptName ขึ้นกับ DeptID (ซึ่งไม่ใช่ PK) ➜ ให้แยก (DeptID, DeptName) ไปเป็นตาราง Department แยกต่างหาก

3. ERD to Relational Schema Conversion

🔗

กฎทอง 3 ข้อในการแปลงความสัมพันธ์ (Relationships)

1. ความสัมพันธ์ 1:1 (One-to-One):

นำ Primary Key ของฝั่งใดฝั่งหนึ่งไปวางเป็น Foreign Key (FK) ในอีกฝั่งหนึ่ง (มักเลือกฝั่งที่มีความเป็น Total Participation/Optionality น้อยกว่า หรือยุบรวมเป็นตารางเดียว)

2. ความสัมพันธ์ 1:N (One-to-Many):

นำ Primary Key ของฝั่ง "1" ไปวางเป็น Foreign Key (FK) ไว้ที่ฝั่ง "Many" (N) เสมอ!
ตัวอย่าง: Department(1) ➜ Employee(N) นำ DeptID ไปเป็น FK ใน Employee

3. ความสัมพันธ์ M:N (Many-to-Many): ออกสอบทุกปี

ต้องสร้างตารางกลาง (Associative Entity / Junction Table) ขึ้นมาใหม่เสมอ!

  • ดึง PK จากทั้งสองตารางมาประกอบกันเป็น Composite Primary Key
  • และแต่ละตัวทำหน้าที่เป็น Foreign Key ชี้กลับไปยังตารางแม่
  • หากความสัมพันธ์มี Attribute เพิ่ม (เช่น เกรด, วันที่สั่งซื้อ) ให้นำมาเก็บไว้ในตารางกลางนี้

4th Octet Analysis

แจกแจงบิต 8 บิตของ Octet ที่ 4 ใน Subnet Mask 255.255.255.192 เพื่อให้เห็นชัดเจนว่าบิตไหนถูกยืมมาเป็น Network Bit (1) และบิตไหนคงเหลือเป็น Host Bit (0)

ลำดับบิต Bit 1 Bit 2 Bit 3 Bit 4 Bit 5 Bit 6 Bit 7 Bit 8
น้ำหนักบิต (Weight) 128 64 32 16 8 4 2 1
Network Bits (บิต 1)

ยืมบิตมา 2 บิต (128 + 64 = 192) เพื่อสร้าง Subnet ใหม่ได้ 2^2 = 4 Subnets

Host Bits (บิต 0)

เหลือบิตโฮสต์ 6 บิต นำไปยกกำลังสองหัก 2 ได้ (2^6 - 2) = 62 Hosts/Subnet

⚠️ 3 ความผิดปกติคลาสสิกของ Process ที่ข้อสอบชอบถาม:
1. Black Hole (หลุมดำ):

Process ที่มีแต่ลูกศรนำข้อมูลเข้า (Inputs) แต่ไม่มีข้อมูลออก (No Outputs) เลย

2. Miracle (ปาฏิหาริย์):

Process ที่มีแต่ลูกศรผลลัพธ์ออก (Outputs) โดยไม่มีกระแสข้อมูลนำเข้า (No Inputs) มาก่อน

3. Gray Hole (หลุมสีเทา):

ข้อมูลที่ป้อนเข้ามา ไม่เพียงพอหรือไม่สอดคล้องที่จะผลิตผลลัพธ์ที่ระบุใน Output
